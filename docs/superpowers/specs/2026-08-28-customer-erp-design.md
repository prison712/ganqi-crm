# 集团销售客户管理 ERP 系统设计

## 1. 目标与范围

本项目交付一个可在单机直接运行的中文客户管理 ERP。系统服务于集团销售部门，围绕私海、公海、客户跟进、人员管理、数据统计和操作审计形成完整闭环。

首期范围包括：

- 管理员和销售账号密码登录。
- 管理员维护销售账号、查看全部客户、分配和释放客户。
- 销售维护自己的私海客户，浏览并领取公海客户。
- 客户搜索、筛选、分页、新增、编辑、软删除、恢复、Excel 导入与导出。
- 客户详情与不可篡改的跟进历史。
- 首页统计卡片与管理员操作日志。
- SQLite 自动初始化、初始管理员、中文 README 和可重复执行的测试。

不纳入首期：多租户、审批流、移动端原生应用、消息推送、云端对象存储、第三方 CRM 集成和复杂 BI 图表。

## 2. 技术架构

采用单仓库、前后端分离的目录结构：

- `client/`：Vite、React、React Router、Ant Design、Axios、Vitest、React Testing Library。
- `server/`：Node.js 24+、Express、Node 内置 `node:sqlite`、JWT、bcryptjs、Multer、SheetJS、Vitest、Supertest。
- `data/`：运行时生成的 SQLite 数据库和导入临时文件，不提交真实数据。
- 根目录：统一脚本、环境变量示例、README 和设计文档。

开发模式下前端与后端分别运行，Vite 将 `/api` 代理到 Express。生产模式下先构建前端，再由 Express 托管 `client/dist`，因此既满足开发体验，也支持一个 Node 进程启动完整系统。

## 3. 身份认证与权限

系统角色固定为：

- 管理员：访问所有客户、回收站、销售账号管理、分配/释放、全部日志和全局统计。
- 销售：访问自己的私海、全部公海、自己客户的详情与跟进；不能读取其他销售的私海、账号管理和全局日志。

认证采用用户名和密码。密码使用 bcrypt 哈希保存，登录成功后返回短期 JWT。前端把令牌保存在 `localStorage`，统一请求层添加 `Authorization: Bearer <token>`。后端中间件完成身份校验与角色授权，前端菜单隐藏只用于体验，不作为安全边界。

初始管理员固定为 `admin/admin123`，仅在数据库中不存在管理员时创建。账号名唯一。销售账号不物理删除，只能启用或停用；重置密码由管理员执行。停用销售时，其名下全部客户（包括回收站中的客户）在同一事务内清空归属；未删除客户立即进入公海，回收站客户恢复后进入公海。系统为每个客户记录释放日志，并另记账号停用日志。

## 4. 数据模型

### 4.1 users

- `id`：整数主键。
- `username`：唯一账号。
- `display_name`：显示姓名。
- `password_hash`：密码哈希。
- `role`：`admin` 或 `sales`。
- `is_active`：是否启用。
- `created_at`、`updated_at`：ISO 时间。

### 4.2 customers

- `id`：整数主键。
- `company_name`：公司名称，必填。
- `contact_name`：联系人。
- `phone`：电话。
- `email`：邮箱。
- `source`：客户来源。
- `status`：`potential`、`following`、`won`、`lost`，分别显示为潜在、跟进中、已成交、流失。
- `notes`：备注。
- `owner_id`：归属销售；为空表示公海。
- `last_followed_at`：最后跟进时间。
- `created_by`：创建人。
- `created_at`、`updated_at`：ISO 时间。
- `deleted_at`、`deleted_by`：软删除信息。

### 4.3 follow_ups

- `id`：整数主键。
- `customer_id`：客户。
- `author_id`：跟进人。
- `followed_at`：跟进时间。
- `content`：跟进内容，必填。
- `next_plan`：下一步计划。
- `created_at`：记录创建时间。

跟进记录只允许新增，不提供编辑与删除，以保留历史。新增跟进后，同一事务更新客户的 `last_followed_at`。

### 4.4 operation_logs

- `id`：整数主键。
- `actor_id`、`actor_name`：操作人快照。
- `action`：领取、释放、分配、导入、软删除、恢复、账号新增、账号编辑、密码重置、账号启停。
- `customer_id`、`customer_name`：可空的客户及名称快照。
- `from_owner_id`、`to_owner_id`：归属变更。
- `details`：JSON 格式补充信息。
- `created_at`：操作时间。

日志不随客户软删除、账号停用或其他业务操作而删除。系统不提供跟进记录和操作日志的编辑、删除接口，数据库外键也不使用级联删除这两类历史数据。

## 5. 关键业务规则

- 私海由 `owner_id` 标识；公海客户的 `owner_id` 为空。
- 销售新增客户默认进入自己的私海；管理员新增时可选择销售或公海。
- 销售只能编辑、软删除和释放自己的私海客户；只能浏览和领取公海客户。释放时必须填写释放原因，去除首尾空格后长度为 2 至 200 字，该原因写入操作日志详情。
- 管理员可编辑任何未删除客户，可把客户分配给销售或释放到公海，并可恢复软删除客户。
- 领取接口单次只接受一个客户 ID，不提供批量领取。领取使用 SQLite 写事务和条件更新：只有 `owner_id IS NULL AND deleted_at IS NULL` 时才能成功，并检查受影响行数。并发领取只有第一人成功，其余请求收到 HTTP 409 和“该客户已被其他销售领取，请刷新列表”的中文提示。
- 分配、释放、领取、软删除、恢复和导入均在数据变更成功后写操作日志，数据与日志处于同一事务。
- 搜索默认匹配公司名称、联系人、电话和邮箱；筛选支持状态、来源和归属；分页参数有最大页大小限制。
- 客户软删除后不出现在业务列表中，管理员可在回收站恢复。销售不能查看回收站。
- 客户恢复时，如果当前归属销售仍启用则保留该归属；如果归属为空或销售已停用则进入公海。软删除和恢复均保留客户跟进与既有操作日志。
- Excel 导入字段为公司名称、联系人、电话、邮箱、来源、备注。公司名称必填，邮箱有值时必须格式合法。
- Excel 判重使用标准化后的“公司名称 + 电话”。公司名称去除首尾空格，电话去除空格和常见连接符；与现有未删除客户或同批前序行重复时跳过。
- 销售导入的客户进入本人私海；管理员导入前选择目标销售或公海。
- 导入逐行处理，错误行不阻断整批。响应返回总行数、成功数、重复数、失败数及逐行中文说明，并写一条批次日志。
- 导入结果中的每条失败或重复记录包含原 Excel 行号、公司名称和中文原因，前端以可复制表格展示。
- 模板下载由后端动态生成 `.xlsx` 文件，包含固定中文表头、一行示例数据和字段说明工作表。
- 导出遵循当前用户权限与页面当前关键词、状态、来源、归属等筛选条件，仅导出未删除客户；文件列名使用中文。前端导出请求复用列表当前查询参数，后端再次执行权限约束，不能通过修改查询参数越权导出。

## 6. API 设计

统一前缀为 `/api`，成功响应使用 `{ data, message? }`，失败响应使用 `{ error: { code, message, details? } }`。主要接口为：

- `POST /auth/login`、`GET /auth/me`。
- `GET/POST /users`、`PATCH /users/:id`、`POST /users/:id/reset-password`、`POST /users/:id/toggle-active`。
- `GET/POST /customers`、`GET/PATCH/DELETE /customers/:id`、`POST /customers/:id/restore`。
- `POST /customers/:id/claim`、`POST /customers/:id/release`、`POST /customers/:id/assign`。
- `GET/POST /customers/:id/follow-ups`。
- `POST /customers/import`、`GET /customers/export`、`GET /customers/import-template`。
- `GET /dashboard/stats`。
- `GET /operation-logs`。

`POST /customers/:id/release` 的请求体必须包含 `reason`。所有客户、跟进、导入导出、统计、账号和日志接口都在后端根据当前 JWT 用户执行对象级权限检查；禁止依赖前端路由或菜单判断权限。

HTTP 状态码语义：参数错误 400、未登录或 JWT 过期 401、无权限 403、资源不存在 404、并发领取或唯一性冲突 409、服务端错误 500。所有预期业务分支都有具体中文提示，例如“只能释放属于自己的客户”“已删除客户不能添加跟进”“停用账号不能登录”“没有权限查看其他销售的客户”；服务端日志保留原始错误堆栈。

## 7. 前端体验与视觉设计

整体采用企业后台布局：深蓝色左侧导航与顶部栏，橙色用于主操作、状态强调和选中态；内容区使用浅灰背景与白色卡片。桌面端优先，宽度低于平板断点时导航折叠、表格允许横向滚动，保证基础响应式可用。

页面包括：

- 登录页：品牌区、账号密码表单、初始账号提示。
- 首页看板：管理员显示今日全局新增、全部私海、公海总数、本周全员跟进次数和最近全局操作；销售显示今日本人新增、我的私海、公海总数、本周本人跟进次数和自己的最近跟进。销售统计查询必须在后端按当前用户 ID 过滤。
- 私海管理：搜索栏、状态/来源筛选、分页表格、新增、编辑、软删除、释放、导入和导出。
- 公海管理：搜索筛选、客户摘要和领取操作；领取前二次确认。
- 客户详情：客户资料、状态与归属、跟进时间线、新增跟进表单。
- 全部客户与回收站：管理员专属；支持分配、释放、恢复。
- 销售账号管理：管理员专属；新增、编辑、启停、重置密码。
- 操作日志：管理员专属；按动作、操作人、时间筛选。

列表空状态、加载状态、接口错误、表单错误和上传结果都提供中文反馈。软删除、恢复、释放、分配、停用账号、重置密码等高影响操作需要说明影响范围的确认对话框；释放对话框同时收集必填原因。状态使用一致的彩色标签，但不只依赖颜色表达含义。

Axios 响应拦截器统一处理 401：清除本地身份信息，保留当前站内地址作为登录后的返回地址，跳转登录页并提示“登录已过期，请重新登录”。为避免重复弹窗，同一批并发 401 只执行一次退出跳转。

## 8. 错误处理与数据安全

- 后端使用参数校验层拒绝缺失、超长和格式错误的输入。
- 所有 SQL 使用预编译参数，不拼接用户输入。
- 上传只接受 `.xlsx`，限制文件大小和行数，处理完成后删除临时文件。
- JWT 密钥通过环境变量配置，开发环境提供明确的示例值；生产启动检测弱密钥并给出警告。
- 密码不进入日志或 API 响应。
- 后端授权采用路由角色校验与服务层对象归属校验两层防护；管理员专属接口拒绝销售访问，客户级操作还要校验归属、公海和删除状态。
- 数据库启动时开启外键约束和 WAL 模式；关键多表写入使用事务。
- 全局错误处理中间件统一隐藏内部实现细节。

## 9. 测试与验收

后端以真实临时 SQLite 数据库执行集成测试，覆盖：

- 初始管理员登录、错误密码和停用账号拒绝登录。
- 管理员与销售的数据可见范围。
- 销售不能读取或修改他人私海客户。
- 公海领取成功、重复/并发领取冲突、释放和管理员分配。
- 客户软删除、列表隐藏、管理员恢复。
- 跟进新增与最后跟进时间更新。
- Excel 成功导入、重复跳过、坏行报告和权限归属。
- 仪表盘统计与操作日志权限。
- 停用销售自动释放其全部私海客户，同时保留并可查询历史跟进和操作日志。
- 释放原因必填、他人客户释放被拒绝、回收站仅管理员访问、跟进记录不能编辑或删除。
- 管理员与销售看板统计口径隔离，销售无法通过请求参数扩大统计范围。

前端测试覆盖登录、权限菜单、列表筛选参数、客户表单、领取确认、导入结果和跟进提交。最终验收运行后端测试、前端测试、前端生产构建，并以真实服务执行一次登录—新增—释放—领取—跟进—导出的端到端冒烟流程。

## 10. 初始化与运行

首次启动后端时使用 `path.resolve(process.cwd(), 'data')` 与 Node 文件 API 创建 `./data` 目录，在其中创建 SQLite 文件和表结构，并插入初始管理员 `admin/admin123`。路径处理不依赖 Unix 命令或路径分隔符，可直接在 Windows PowerShell 运行。

提供幂等的 `npm run seed:demo` 模拟数据脚本，一键创建管理员之外的测试销售账号、覆盖四种状态且同时分布于私海与公海的测试客户、跟进记录和对应操作日志。脚本输出测试账号与密码；重复执行前清理此前带固定演示标识的数据，不影响用户自行创建的数据。

README 提供 Node.js 版本要求、依赖安装、开发启动、生产构建与启动、数据库初始化/重置、模拟数据、Excel 模板使用说明，以及 Windows 常见故障排查：端口占用、原生 SQLite 依赖安装失败、数据库文件被锁定、JWT 密钥缺失、PowerShell 执行策略和前端代理无法连接后端。

根目录提供统一命令，支持一次安装所有工作区依赖、同时启动前后端、运行全部测试和完成生产构建。

## 11. 完成标准

- 管理员和销售可使用真实账号登录，权限隔离由后端验证。
- 私海、公海、领取、释放、分配和软删除流程可真实操作且日志完整。
- 客户 CRUD、筛选分页、跟进、Excel 导入导出均通过接口与界面联调。
- 首页统计使用数据库真实数据。
- 初始管理员、数据库初始化和启动步骤与 README 一致。
- 自动化测试和生产构建通过，核心冒烟流程通过。
- `npm run seed:demo` 可重复生成演示数据，SQLite 文件位于根目录 `data/`，Windows PowerShell 下的全部 README 命令可执行。
