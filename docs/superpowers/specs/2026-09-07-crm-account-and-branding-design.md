# CRM 账号体系与品牌界面迭代设计

## 目标

在不改变客户公海/私海、跟进、Excel、操作日志、看板和公共资料业务规则的前提下，完善密码自助管理、管理员子账号、销售账号软删除与资料编辑，并将页面品牌从 ERP 统一更新为 CRM。

## 身份与权限模型

- 继续沿用 `users.role` 的 `admin`、`sales` 两种值，避免影响现有管理员权限判断。
- 在 `users` 表新增 `is_super_admin INTEGER NOT NULL DEFAULT 0`。
- 旧数据库迁移时，如果不存在超级管理员，则把创建时间最早、编号最小的有效管理员标记为超级管理员。初始化创建的 `admin` 账号直接标记为超级管理员。
- 超级管理员和子管理员都拥有现有管理员业务权限，包括全部客户、客户与资料回收站、账号管理、操作日志、统计看板和客户分配。
- 只有超级管理员可以创建管理员子账号。普通子管理员不能创建管理员，也不能修改、停用或删除超级管理员。
- 本次只新增销售账号删除；管理员账号不提供删除入口。这样超级管理员始终受到保护，且不引入未要求的管理员生命周期功能。
- 所有权限必须由后端接口校验，前端菜单与按钮隐藏只用于界面展示。

## 用户表兼容迁移

`users` 表新增：

- `is_super_admin`：是否为超级管理员。
- `deleted_at`：账号软删除时间，空值表示未删除。
- `deleted_by`：执行删除的管理员编号。

迁移通过启动时检查 `PRAGMA table_info(users)` 后按缺失字段逐项 `ALTER TABLE`，兼容现有 SQLite 数据库。登录、鉴权和账号列表都排除软删除账号；用户数据行不物理删除，确保跟进记录外键、客户创建人以及历史审计信息继续有效。

## 密码管理

- 保留现有 `POST /api/auth/change-password`，所有登录用户均可调用。
- 必须校验当前密码；新密码必须为 8–128 位，同时包含英文字母和数字，不允许与当前密码相同。
- 创建账号、管理员重置密码与用户自助改密使用同一套后端密码规则。
- 修改成功后立即更新密码哈希和更新时间，旧密码不能再次登录；当前登录会话继续有效，避免首次强制改密后再次登录。
- 前端右上角个人菜单增加“个人中心/修改密码”入口。首次登录仍使用不可关闭的强制改密弹窗，日常修改使用可关闭弹窗。
- 密码字段和错误详情不写入操作日志；只记录操作类型、目标账号编号和操作人。

## 管理员子账号

- 扩展 `POST /api/users`，接收 `role`。缺省仍为 `sales`，兼容现有调用。
- 当 `role=admin` 时，后端要求当前用户为超级管理员；新账号固定为普通子管理员。
- 账号列表返回 `role`、`isSuperAdmin`、`isDeleted` 等公开字段，不返回密码哈希。
- 超级管理员界面提供“新增管理员”入口并显示“超级管理员/子管理员/销售”身份标签；普通子管理员仍可管理销售账号，但看不到创建管理员入口。

## 销售账号编辑、停用与删除

- `PATCH /api/users/:id` 支持销售账号的 `username` 与 `displayName` 修改。
- 登录账号统一校验为 3–30 位字母、数字或下划线，并在数据库唯一约束冲突时返回明确中文提示。
- 保留现有启用/停用能力。停用仍自动释放该销售名下全部客户。
- 新增销售账号软删除接口。删除使用数据库事务完成：释放名下全部客户、填写 `deleted_at/deleted_by`、停用账号，并写入 `account_deleted` 操作日志。
- 删除操作必须二次确认；删除后的账号不能登录，不出现在常规账号列表中，也不能再次启用、编辑或重置密码。
- 删除销售不会删除客户、历史跟进或既有操作日志。自动释放的每位客户继续写入独立释放日志，原因标记为“销售账号删除自动释放”。

## 前端与品牌

- 所有用户可见页面、浏览器标题、导航栏、表单、弹窗、提示和页脚中的 `ERP` 统一替换为 `CRM`；测试名称和纯开发文档不属于页面文本，但用户操作说明和 README 的产品名称同步更新。
- 将用户提供的 `黑字公司logo.png` 复制为前端公共静态资源，保留原图内容。
- 登录页用公司 Logo 替换橙色 `G` 标记，位置与参考图一致；侧边栏品牌区使用适合深色背景的白色承载框展示同一 Logo；浏览器 favicon 使用同一资源。
- Logo 使用 `object-fit: contain`，不拉伸、不裁切原图；窄屏继续遵循现有登录页响应式布局。
- 页面整体深蓝与橙色主题、现有结构和交互布局保持不变。

## 接口错误与审计

后端对未登录、非管理员、非超级管理员、目标账号不存在、账号已删除、登录名重复、当前密码错误和密码格式不合规分别返回中文业务错误。新增日志动作 `account_deleted`，并在前端操作日志与首页动态中显示为“删除账号”。

## 测试与验收

- 数据库迁移测试：旧表自动增加字段，现有管理员自动成为超级管理员，重复启动不改变身份。
- 密码测试：销售与管理员均可自助改密；旧密码错误、纯数字、纯字母、过短和同密码均被拒绝；新密码生效。
- 管理员测试：超级管理员可创建子管理员；子管理员可执行原管理员业务，但不能创建管理员或操作超级管理员。
- 销售账号测试：登录名和姓名可修改；重复账号被拒绝；软删除自动释放客户并保留跟进和日志；删除账号禁止登录。
- 前端测试：个人中心入口、管理员身份标签、销售编辑与删除确认、CRM 文案和 Logo 均正确呈现。
- 回归：执行完整后端与前端测试、生产构建，并验证登录页和登录后关键页面无空白或错误覆盖层。

## 非目标

- 不新增复杂 RBAC 权限表。
- 不提供管理员账号删除、停用或角色转换。
- 不迁移 SQLite、不改变 JWT 有效期、不改变客户和公共资料业务规则。
- 不改造页面视觉主题或重新设计导航结构。
