# 公共资料库功能设计

## 1. 目标与范围

在现有集团销售客户管理 ERP 中新增“公共资料”模块，供所有已登录的管理员和销售共同查阅、上传与下载业务资料。首期先适配当前 Windows 局域网部署，同时保证下周迁移到独立服务器时不需要重写业务代码。

首期范围包括：

- 所有已登录用户查看、搜索、筛选、上传、预览和下载公共资料。
- 上传者删除自己上传的资料，管理员删除任意资料。
- PDF 和图片在线预览，其他允许类型通过附件下载。
- 资料分类、上传说明、上传人、文件大小和上传时间展示。
- 资料软删除、管理员回收站恢复与彻底删除。
- 上传、删除、恢复和彻底删除写入现有操作日志。
- 文件存储目录可配置，支持从局域网电脑平滑迁移到 Windows 或 Linux 服务器。

首期不包括：匿名访问、外链分享、多层文件夹、文件版本管理、在线编辑 Office 文件、全文内容检索、云对象存储和自动病毒查杀。存储层保留替换边界，后续可接入 NAS 或对象存储。

## 2. 总体架构

采用“文件本体存磁盘、业务元数据存 SQLite”的方式：

- 文件默认保存在项目根目录 `./data/uploads`。
- 环境变量 `UPLOAD_DIR` 可以指定其他相对或绝对目录。
- 数据库只保存服务器生成的随机存储标识，不保存 Windows 绝对路径。
- 原始文件名只用于界面展示和下载响应，不直接作为磁盘文件名。
- 前端始终通过同源 `/api` 访问资料，不写死局域网 IP、服务器地址或域名。
- 后端通过受 JWT 保护的接口读取文件，不把上传目录注册为公开静态目录。

新增独立的本地存储模块，对业务层提供以下能力：

- `save`：把已校验的临时文件保存为随机存储标识。
- `open`：为预览或下载创建只读文件流。
- `exists`：确认数据库记录对应的文件是否存在。
- `remove`：在管理员彻底删除时移除文件。

业务接口只依赖这些能力。未来切换 NAS 或对象存储时，可以替换存储模块而不改变前端路由、数据库业务字段和权限逻辑。

## 3. 数据模型

新增 `public_documents` 表：

- `id`：整数主键。
- `original_name`：用户上传时的原始文件名。
- `storage_key`：服务器生成的随机存储标识，唯一且不可由用户指定。
- `category`：`policy`、`product`、`sales_tool`、`training`、`other`，分别显示为制度文件、产品资料、销售工具、培训资料、其他。
- `description`：上传说明，选填，最多 500 字。
- `extension`：规范化的小写扩展名。
- `mime_type`：校验后的响应内容类型。
- `size_bytes`：文件字节数。
- `sha256`：上传完成时计算的内容摘要，用于完整性检查和后续迁移校验；首期不使用摘要阻止重复上传。
- `uploaded_by`：上传用户 ID，关联 `users`。
- `created_at`：上传完成时间。
- `deleted_at`、`deleted_by`：软删除信息。

为常用查询增加以下索引：

- 未删除状态与上传时间索引。
- 分类与上传时间索引。
- 上传人索引。
- 回收站删除时间索引。

同名文件允许存在，系统不会覆盖旧文件。列表通过上传人、上传时间、大小和资料 ID 区分不同记录。

账号停用不会删除资料，也不会改变上传人历史。停用用户上传的既有资料仍可查阅，管理员仍可管理。

## 4. 文件与分类规则

单个文件最大 50 MB，每批最多上传 10 个文件。允许的扩展名为：

- PDF：`.pdf`
- Word：`.doc`、`.docx`
- Excel：`.xls`、`.xlsx`
- PowerPoint：`.ppt`、`.pptx`
- 图片：`.jpg`、`.jpeg`、`.png`、`.gif`、`.webp`
- 文本：`.txt`
- 压缩包：`.zip`

后端不能只相信浏览器传入的文件名和 MIME 类型，需要联合校验扩展名、MIME 类型及文件头或容器特征。可执行文件、脚本文件、双重伪装扩展名和无法识别的内容全部拒绝。系统不解压 ZIP，因此不执行压缩包内文件，也不受解压炸弹影响。

上传使用磁盘临时文件而非内存缓存，避免多个 50 MB 文件同时上传时占满 Node.js 内存。每个文件独立校验并返回成功或失败结果；单个文件失败不阻断同批其他合法文件。

## 5. 权限设计

所有资料权限均由后端根据 JWT 当前用户强制执行：

- 管理员和销售：查看未删除资料列表、查看详情、上传、预览和下载。
- 上传者：软删除自己上传且尚未删除的资料。
- 管理员：软删除任意资料，查看资料回收站，恢复资料和彻底删除资料。
- 销售：不能查看资料回收站，不能删除其他人上传的资料，不能恢复或彻底删除资料。
- 未登录用户：所有资料接口均返回 401，不能通过文件 URL 绕过登录。

前端菜单和按钮根据角色及上传人隐藏，只改善使用体验，不作为安全依据。后端在每次删除、恢复、预览和下载前重新查询资料状态与权限。

## 6. 关键业务流程

### 6.1 上传

1. 用户选择分类、填写可选说明并选择一个或多个文件。
2. 后端逐个执行数量、大小、扩展名、MIME 类型和文件内容校验。
3. 合法文件写入临时位置，同时计算 SHA-256。
4. 存储模块生成不可猜测的 `storage_key`，将临时文件移动到正式目录。
5. 数据库写入资料记录和操作日志。
6. 如果文件保存成功但数据库事务失败，自动删除刚保存的文件；如果磁盘写入失败，则不创建资料记录。
7. 响应返回每个文件的原始文件名、结果类型和中文原因，前端展示批次汇总。

### 6.2 查阅与下载

- 列表默认按上传时间倒序展示未删除资料。
- 搜索匹配原始文件名和资料说明；筛选支持分类和上传人；分页有最大页大小限制。
- PDF 与图片通过受保护的预览接口以内联方式响应。
- Word、Excel、PPT、TXT 和 ZIP 使用附件下载响应。
- 下载文件名使用安全编码后的原始文件名，响应设置 `X-Content-Type-Options: nosniff`。
- 预览和下载都不暴露真实磁盘路径或 `storage_key`。
- 数据库记录存在但文件丢失时，返回“资料文件不存在或已损坏，请联系管理员”，并在服务端记录诊断信息。

### 6.3 删除与恢复

- 普通删除仅写入 `deleted_at` 和 `deleted_by`，文件仍保存在磁盘中。
- 上传者可软删除自己的资料；管理员可软删除任何资料。
- 所有删除操作必须在前端二次确认，后端再次检查权限与当前状态。
- 管理员在资料回收站中可以恢复资料，恢复后重新进入公共列表。
- 管理员可以二次确认后彻底删除。系统先确认目标文件位于配置的上传目录内，再删除磁盘文件和数据库资料记录。
- 彻底删除前写入包含资料名称、上传人、大小和存储摘要的操作日志快照；操作日志不随资料记录删除。
- 如果磁盘文件删除失败，不删除数据库记录，并返回明确中文错误，避免产生无法追踪的孤立文件。

## 7. API 设计

统一前缀为 `/api/documents`，沿用现有成功和失败响应格式。

- `GET /api/documents`：所有登录用户查看未删除资料，支持 `keyword`、`category`、`uploaderId`、`page`、`pageSize`。
- `POST /api/documents`：所有登录用户上传，使用 `multipart/form-data`，文件字段为 `files`，每批最多 10 个。
- `GET /api/documents/:id/preview`：仅对 PDF 和图片返回内联预览。
- `GET /api/documents/:id/download`：返回附件下载。
- `DELETE /api/documents/:id`：上传者删除自己的资料，管理员删除任意资料；执行软删除。
- `GET /api/documents/recycle`：管理员查看资料回收站。
- `POST /api/documents/:id/restore`：管理员恢复资料。
- `DELETE /api/documents/:id/purge`：管理员彻底删除文件与资料记录。

预期错误使用明确的中文业务提示，例如：

- “请选择要上传的资料”
- “单次最多上传 10 个文件”
- “文件不能超过 50 MB”
- “不支持该文件格式”
- “文件内容与扩展名不一致”
- “只能删除自己上传的资料”
- “只有管理员可以查看资料回收站”
- “该资料已被删除，请刷新列表”
- “资料文件不存在或已损坏，请联系管理员”
- “磁盘空间不足，资料上传失败”

## 8. 前端设计

所有登录用户的左侧菜单增加“公共资料”，沿用现有深蓝色与橙色企业后台风格。

公共资料页包含：

- 页面标题与简短说明。
- 文件名关键词、分类和上传人筛选。
- 上传资料按钮及上传弹窗。
- 分页表格，展示资料名称、分类、说明、文件类型、大小、上传人和上传时间。
- PDF/图片显示“预览”，所有资料显示“下载”。
- 当前用户上传的资料显示“删除”；管理员对所有资料显示“删除”。
- 上传完成后展示成功数和失败数，并逐文件显示中文结果。
- 空列表、加载、下载失败和预览失败均提供中文反馈。

PDF 与图片预览使用对话框或新页面承载，文件内容通过携带 JWT 的请求获取 Blob URL，关闭预览后及时释放临时 URL。不能把带 JWT 的永久地址写入页面或日志。

管理员额外拥有“资料回收站”页面，展示删除人和删除时间，并提供恢复与彻底删除操作。彻底删除对话框明确提示“文件将从磁盘移除且不可恢复”。

## 9. 操作日志

复用现有 `operation_logs` 表，通过 `details` JSON 保存资料信息，不新增可修改或删除日志的接口。新增动作：

- `document_upload`：每个成功文件一条，包含资料 ID、文件名、分类、大小和 SHA-256。
- `document_delete`：软删除，包含资料 ID、文件名和原上传人。
- `document_restore`：管理员恢复资料。
- `document_purge`：管理员彻底删除，保留删除前完整业务快照。

首期不记录每次预览和下载，避免高频查阅产生大量低价值日志。后续如有合规审计要求，可增加单独的访问审计表。

## 10. 安全与异常处理

- 上传目录不在前端静态资源目录内，也不由 Express 静态中间件直接暴露。
- 所有路径由服务器生成的 `storage_key` 构造，并通过规范化路径校验确保最终路径位于 `UPLOAD_DIR` 内。
- 文件名移除控制字符，仅用于 `Content-Disposition` 展示。
- 文件流使用背压机制，不把整个文件读入内存。
- 上传临时文件在成功、校验失败和异常退出路径中都会被清理。
- 服务器启动时检查上传目录能否创建和写入；不可写时给出明确启动错误。
- SQLite 记录与文件系统无法组成真正的原子事务，因此通过“保存失败回滚记录、记录失败清理文件”的补偿流程保持一致。
- 全局错误处理中间件不向前端暴露真实磁盘路径、堆栈和内部错误信息。
- 局域网阶段继续限制 Windows 防火墙为 `LocalSubnet`；服务器上线后使用 HTTPS 反向代理、强 JWT 密钥、目录备份和最小文件系统权限。

## 11. 测试与验收

后端自动化测试覆盖：

- 管理员和销售成功上传允许类型。
- 未登录上传、列表、预览和下载被拒绝。
- 文件数量、大小、扩展名、MIME 类型和文件特征校验。
- 多文件部分成功时逐文件返回结果。
- 搜索、分类、上传人筛选和分页。
- PDF/图片预览与其他文件下载响应头。
- 上传者删除自己的资料、销售越权删除被拒绝、管理员删除任意资料。
- 软删除后普通列表不可见，管理员可查看回收站并恢复。
- 管理员彻底删除后文件消失、业务记录消失、操作日志保留。
- 数据库写入失败、磁盘写入失败和磁盘文件丢失时的一致性处理。
- 路径穿越、伪装文件和非法 `storage_key` 不能访问上传目录外文件。

前端自动化测试覆盖：

- 管理员和销售都能看到公共资料菜单。
- 筛选与分页参数正确传递。
- 上传表单校验、批量结果展示和错误提示。
- PDF/图片预览入口和其他文件下载入口。
- 上传者、其他销售和管理员看到正确的删除按钮。
- 删除与彻底删除二次确认。
- 资料回收站仅管理员可见。

最终验收执行完整前后端测试、生产构建，并通过真实局域网服务验证登录、上传、列表、预览、下载、删除和恢复流程。

## 12. 部署、备份与服务器迁移

环境变量增加：

```text
UPLOAD_DIR=data/uploads
MAX_UPLOAD_FILE_MB=50
MAX_UPLOAD_FILES=10
```

相对 `UPLOAD_DIR` 以项目根目录解析，Windows 和 Linux 均使用 Node.js 路径 API 处理。`data/uploads`、上传临时目录和资料备份不提交 Git。

当前局域网部署升级步骤：

1. 停止正在运行的 Node.js 服务。
2. 备份 `data/customer-erp.sqlite` 及其 WAL 文件，并备份 `data/uploads`。
3. 安装依赖、运行数据库自动迁移、构建前端并重新启动服务。
4. 验证局域网地址的资料上传、预览和下载。

迁移服务器时：

1. 停止旧电脑写入，执行 SQLite checkpoint 后备份数据库。
2. 完整复制数据库与上传目录，保持相对目录结构或设置新的 `UPLOAD_DIR`。
3. 在新服务器设置生产环境、强随机 JWT 密钥和上传目录权限。
4. 启动前先运行完整性校验，按 `storage_key` 与 SHA-256 检查数据库和文件对应关系。
5. 使用 HTTPS 反向代理对外提供服务，再切换用户访问地址。

数据库与上传目录必须作为同一个备份集合保存。只备份 SQLite 会丢失文件本体，只备份上传目录会丢失分类、上传人和删除状态。

## 13. 完成标准

- 所有已登录用户可以真实上传、查阅、预览和下载公共资料。
- 上传者只能删除自己的资料，管理员可以管理全部资料和资料回收站。
- 文件类型、数量和 50 MB 大小限制由后端强制执行。
- PDF 与图片可安全预览，其他允许类型可下载。
- 上传、软删除、恢复和彻底删除日志完整且不可通过业务接口删除。
- 文件失败与数据库失败不会留下不可追踪的记录或文件。
- 局域网部署可运行，上传目录不公开暴露。
- SQLite 与上传目录可按文档迁移至 Windows 或 Linux 服务器。
- 全部自动化测试、生产构建和真实服务冒烟验证通过。
